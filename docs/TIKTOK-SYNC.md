# TikTok manual performance sync

Published content includes a Refresh TikTok button for each linked video. It sends `{ "videoId": "..." }` to the existing authenticated sync endpoint; only that video's TikTok statistics are queried and saved. Empty requests from Settings still sync the entire list. Duplicate-link checks remain tracker-wide. Both flows retain credential/version checks, write locks, correction history and no automatic write retries.

Configure a TikTok developer app with Login Kit and Display API, granting `user.info.basic` and `video.list`. Production access depends on TikTok approval; Sandbox access is limited to configured target users. Save `TIKTOK_CLIENT_KEY` and Sensitive `TIKTOK_CLIENT_SECRET` directly in this project's Vercel environment. Register exactly `https://content-studio-xi-peach.vercel.app/api/tiktok/callback` as the Login Kit Web redirect URI. Deploy once after configuring credentials.

Settings → Connect TikTok → approve your account → Continue to app → Sync TikTok. Token exchange and refresh occur only on the server. No token copying, scheduling, browser token storage or publishing permission is needed. The confidential Web flow uses client-secret authentication and random browser-bound OAuth state, as documented by TikTok's Web Login Kit; mobile/desktop PKCE parameters are not assumed to apply to this Web client.

Credentials and OAuth attempts use AES-256-GCM with fresh IVs and HKDF keys scoped to TikTok, client key, origin and purpose. They are stored in this project's private Blob store, separated from Google and Instagram. Reads bypass caches. ETag writes prevent stale callback/refresh replacement. Create-only claims make callbacks single-use and refresh-token consumption exclusive across server instances. Uncertain exchanges or writes are not retried. If refresh rotation succeeds but persistence cannot be confirmed, reconnect instead of consuming the old refresh token again. No tokens, provider response bodies or provider error messages are logged or sent to browsers.

Sync refreshes views, likes, comments and shares on today's TikTok observation, including manual ones. Previous values stay in correction history. Missing values stay unchanged; measured zero is retained. Duration, watch metrics, saves, older dates, Instagram and YouTube remain untouched. Full `https://www.tiktok.com/@name/video/123...` links are matched directly. Official `vt.tiktok.com` and `vm.tiktok.com` short links are resolved with credential-free HEAD requests, at most four HTTPS redirects within a fixed TikTok hostname allowlist. Other URLs, ports, embedded credentials, external redirects and arbitrary provider URLs are never fetched. Resolution is limited to four concurrent reads and a 60-second total budget; unresolved links are reported as unmatched. At most 100 linked videos are queried in batches of 20. Query Videos verifies that videos belong to the authorized user.

All provider reads complete before the existing Google Sheets lock and one atomic snapshot/metadata commit. Video link/version and snapshot version are rechecked. Duplicate observations, changed credentials, formulas and metadata conflicts block writes. No changes to ideas, published records, formulas, formatting or tabs are made by authorization. Sync is only an authenticated, same-origin POST; all existing authentication remains intact.

Automated tests use fake TikTok and private Blob responses and mocked spreadsheet APIs. Production app approval, real consent and actual video/statistics availability must be verified separately by the account owner.

Official references: [Web Login Kit](https://developers.tiktok.com/docs/en/login-kit-web), [token exchange](https://developers.tiktok.com/docs/en/oauth-get-a-user-access-token), [token management](https://developers.tiktok.com/docs/en/oauth-user-access-token-management), [Query Videos](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-query), and [User Info](https://developers.tiktok.com/docs/en/tiktok-api-v2-get-user-info).
